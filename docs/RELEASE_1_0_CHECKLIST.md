# Apache Hop MCP 1.0 release gate

Version 1.0 is releasable only when every mandatory gate below has objective evidence.

## Build and compatibility

- [x] `mvn -B clean verify` passes on Java 21 with the Apache Hop 2.19.0 compile baseline.
- [x] `mvn -B -P hop-2.20 clean verify` passes against the locally installed 2.20.0-SNAPSHOT artifacts.
- [x] The generated protocol and `hop_config` versions are `1.0.0`.
- [x] Maven, both Marketplace catalogs, the ZIP filename and configured GitHub tag all use `1.0.0` / `v1.0.0`.

## Protocol and behavior

- [x] The STDIO contract test completes `initialize` and `notifications/initialized` before tool calls.
- [x] Multiple consecutive tool calls complete in one MCP session.
- [x] Structural validation, native preview, apply, reload and rollback tests pass.
- [x] Execution, mutation, deep checking and Hop Web access remain independently disabled by default.
- [x] An installed Hop 2.20 runtime advertises server version `1.0.0`, completes the MCP 2024-11-05 handshake, and serves consecutive definition validations in one external `hop.bat mcp` process.

## Security and packaging

- [x] Traversal, symlink escape, XXE/DTD, secret redaction, bounds and SHA-256 precondition tests pass.
- [x] `target/apache-hop-mcp-1.0.0.zip` contains `plugins/misc/apache-hop-mcp/`.
- [x] The ZIP does not contain `hop-core`, `hop-engine` or `hop-ui` jars.
- [x] STDOUT contains JSON-RPC only; application and Hop logs go to STDERR.
- [ ] A clean Hop installation can install the ZIP, discover `hop mcp`, and complete a read-only smoke test.

## Release

- [x] `CHANGELOG.md`, `RELEASE_NOTES.md`, `README.md` and `SECURITY.md` describe the 1.0 contract.
- [ ] The release commit is tagged `v1.0.0` only after CI and Marketplace ZIP validation pass.
- [ ] The GitHub release contains the ZIP and checksums generated by the release workflow.
- [ ] The published Marketplace catalog resolves and installs the released artifact.
